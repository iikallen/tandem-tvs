# Stage 2 acceptance contract

This is the executable acceptance map for Stage 2. A checkbox means the criterion is planned;
only `STAGE2_REPORT.md` may later record observed PASS evidence. Phase 2.0 evidence is listed
separately because it is complete before publication work starts.

## Phase 2.0 gate

- [x] Branch starts from clean Stage 1 release commit
      `84294fd302cc2a279bdcc7b2e64b25b63bbcc8ec`.
- [x] Exact release baseline has a successful clean-run literal `make prod` result in GitHub
      Actions run `32626917307`.
- [x] Employee lookup is non-enumerating, input/result bounded, and data-minimized.
- [x] Personalized Stage 1 endpoints emit private/no-store cache directives.
- [x] Swagger/schema are authenticated when enabled, use local locked assets, and are absent
      in production.
- [x] Stale organization units are atomically soft-deactivated and reactivation is tested.
- [x] Backend and frontend start healthy as non-root with read-only roots and reduced
      privileges.
- [x] Automated responsive coverage runs at 360, 390, 768, and 1440 px without horizontal
      overflow.
- [x] No publication, comment, reaction, or later-stage feature is included in Phase 2.0.

## Domain and migrations

- [x] `apps/publications` owns publication, category, audience, and view behavior.
- [x] `apps/publications` owns append-only audit behavior after Phase 2.3.
- [x] Publication IDs are UUIDs; slugs and database constraints are deterministic.
- [x] Only `DRAFT` and `PUBLISHED` are active Stage 2 statuses.
- [x] Structured rich text accepts only the Stage 2 whitelist and rejects executable or
      unknown content.
- [x] Search text is generated by the server.
- [x] Categories support stable slug, ordering, and active state.
- [x] `(publication, user)` view uniqueness is enforced by PostgreSQL.
- [x] Required visibility, ordering, lookup, and search indexes exist.
- [x] Migration drift check is clean.

## Authorization and addressing

- [x] `visible_to(user)` is the sole employee-facing publication queryset boundary.
- [x] `ALL` reaches active employees.
- [x] `ORG_UNIT` reaches only an employee in the exact active addressed unit.
- [x] `EMPLOYEE` reaches only the selected portal identity.
- [x] `MODULE_ROLE` reaches only an employee with the exact projected role.
- [x] Multiple rules use documented union semantics; `ALL` cannot be combined with narrower
      rules.
- [x] Drafts and inactive publications never enter employee querysets.
- [x] Unknown, inactive, and Stage 1 blocked users receive no publication access.
- [x] A non-addressed employee sees no feed row.
- [x] A non-addressed employee receives not found from the direct detail URL.
- [x] A non-addressed publication never appears in search or unread results.
- [x] Inactive/stale organization projections never grant access.

## Editorial API

- [x] Editor and administrator roles may create, edit drafts, define audiences, and publish.
- [x] Employee role is denied by the server, regardless of frontend visibility.
- [x] Creation derives author from `request.user` and rejects a client-supplied author.
- [x] Publish validates title, summary, body, active category, and at least one valid audience.
- [x] Publish sets `published_at` server-side in a transaction.
- [x] Create, update, and publish append attributable immutable audit events.

## Feed, detail, search, unread, and views

- [x] Feed is ordered by `published_at DESC, id DESC`.
- [x] Stable cursor pagination defaults to 20 and cannot exceed 50.
- [x] Category, author, date-from, date-to, unread, and query filters work together.
- [x] Empty and oversized queries are bounded.
- [x] Title, summary, and normalized body search work in PostgreSQL.
- [x] Detail rendering records first/last view idempotently.
- [x] Repeat opens by one user do not increase unique views.
- [x] Unread status corresponds to absence of that user's `PublicationView`.
- [x] Stage 3 counts, if retained in the response contract, remain zero without creating Stage
      3 domains.

## React application

- [x] `/news` and `/news/:publicationId` follow the supplied UI Kit.
- [x] Editorial routes are present only for permitted roles and remain server-protected.
- [x] Feed supports search, all/unread, category, author, period, and infinite loading.
- [x] Loading, empty feed, empty search, unavailable, unauthorized, and normal states exist.
- [x] Publication detail and preview share the safe structured-content renderer.
- [x] Minimal editor includes paragraph, H2, H3, bold, italic, bullet/ordered list, quote, and
      link only.
- [x] Audience selector uses bounded employee and active organization APIs.
- [x] Keyboard navigation, labels, focus visibility, and automated accessibility checks pass.
- [x] 360, 390, 768, and 1440 px tests pass without horizontal overflow.

## Vertical-slice end-to-end proof

- [x] Editor creates and publishes `Регламент VPN` for an organization unit.
- [x] An employee in that unit sees it in feed, detail, search, and unread.
- [x] An employee outside that unit sees it in none of those surfaces.
- [x] The outside employee's direct URL is denied without disclosing the publication.
- [x] A repeat detail open leaves unique view count unchanged.

- [ ] Literal `make prod` passes on a clean local/CI environment.
